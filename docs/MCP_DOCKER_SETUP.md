# Shinobi MCP Server - Docker Setup (Recommended)

## Why Docker?

Using Docker for the Shinobi MCP server solves portability issues:
- ✅ **No path conflicts** - works on any developer machine
- ✅ **Consistent environment** - same Node version, dependencies
- ✅ **No `pnpm` output pollution** - clean stdio protocol
- ✅ **Isolated** - doesn't interfere with local dev environment

## Quick Setup

### 1. Start Docker Desktop

Ensure Docker is running on your machine.

### 2. Run Setup Script

```bash
cd /path/to/shinobi
./bin/setup-cursor-mcp
```

This will:
- Build the Docker image
- Generate the MCP config entry for your machine
- Show you what to add to `~/.cursor/mcp.json`

### 3. Update Cursor MCP Config

The script will output something like:

```json
{
  "mcpServers": {
    "shinobi": {
      "command": "/Users/yourname/project42/shinobi/bin/shinobi-mcp-docker",
      "env": {
        "NODE_ENV": "development"
      }
    }
  }
}
```

Add this to your `~/.cursor/mcp.json` (merge with existing config).

### 4. Restart Cursor

Completely quit Cursor (Cmd+Q) and relaunch.

### 5. Verify

Check Cursor's MCP server list - you should see "shinobi" with 69 tools and 9 resources.

## Manual Docker Commands

### Build Image

```bash
docker build -t shinobi-mcp-server:latest \
  -f apps/shinobi-mcp-server/Dockerfile .
```

### Test Locally

```bash
# Test the MCP server
echo '{"jsonrpc":"2.0","method":"ping","id":1}' | ./bin/shinobi-mcp-docker
```

Should output: `{"result":{},"jsonrpc":"2.0","id":1}`

### Rebuild After Changes

```bash
# Rebuild image after code changes
docker build -t shinobi-mcp-server:latest \
  -f apps/shinobi-mcp-server/Dockerfile . --no-cache

# Restart Cursor to pick up changes
```

## How It Works

1. **`bin/shinobi-mcp-docker`** - Wrapper script that:
   - Builds Docker image if needed
   - Runs container with stdin/stdout piping
   - Sets environment variables for MCP stdio mode

2. **Docker stdio mode** - Container runs with:
   - `-i` (interactive) for stdin/stdout
   - `--rm` (auto-remove after exit)
   - Volume mounts for `platform-kb` and `packages/components`
   - `MCP_TRANSPORT=stdio` env var (tells logger to use stderr)

3. **Logger routing**:
   - Detects `MCP_TRANSPORT=stdio`
   - Writes logs to stderr (not stdout)
   - Keeps stdout clean for JSON-RPC protocol

## Troubleshooting

### Container won't start

```bash
# Check Docker is running
docker ps

# View build logs
docker build -t shinobi-mcp-server:latest \
  -f apps/shinobi-mcp-server/Dockerfile . 2>&1 | tee build.log
```

### MCP server not showing in Cursor

1. Check logs: `~/Library/Application Support/Cursor/logs/*/window*/exthost/anysphere.cursor-mcp/MCP user-shinobi.log`
2. Verify config path is correct in `~/.cursor/mcp.json`
3. Ensure script is executable: `chmod +x bin/shinobi-mcp-docker`

### Agent mode still crashes

1. Test server manually: `echo '{"jsonrpc":"2.0","method":"ping","id":1}' | ./bin/shinobi-mcp-docker`
2. Check nothing is written to stdout except JSON-RPC
3. Verify stderr contains logs, not stdout
